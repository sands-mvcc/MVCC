Key terms
Public key (e, n)
Shared with everyone. Encrypts messages to its owner, and verifies the owner's signatures.
Private key (d)
Never shared. Decrypts, and makes signatures.
Modulus n
p × q, two secret primes multiplied. Its size (2048 bits) is the key size.
OAEP
Random padding added before RSA encryption, so the same message never encrypts the same way twice.
PSS
The modern padding scheme for RSA signatures.
Hash (SHA-256)
A fixed-size fingerprint of any data. Change one character and the fingerprint changes completely.
Hybrid encryption
RSA locks a random AES key, and AES encrypts the message itself.

Padlocks and seals

Every RSA key pair does two jobs. As a padlock, it lets anyone lock a message that only the owner can open. As a seal, it lets only the owner sign something that anyone can check.

Why real RSA never works like this

"Textbook" RSA is deterministic: the same input always gives the same output, so repeated letters show up as repeated numbers and Eve can run frequency analysis, or simply encrypt guesses with the public key and compare. Real systems add random padding (OAEP) before encrypting, so the same message encrypts differently every time. You'll see that in the next tab.

Why one changed letter breaks everything

A hash function scrambles its input so thoroughly that changing a single character changes about half the bits of the output (the avalanche effect). The signature was made over the original hash, so it can't match the new one. And because only Alice's private key can produce a signature that her public key accepts, Mallory can't make a fresh one either, which is what the Mallory's-key option shows from the other side.

Hybrid RSA + AES

RSA can only lock a couple of hundred bytes, and it's slow. So real systems use it to lock something small: a random AES key. AES, which is fast and has no size limit, encrypts the actual message. This is how PGP and S/MIME email, and cloud "envelope encryption", work.

Running it with a class

Eve's attack. Students playing Eve write down n and the ciphertext, open Factoring race, choose "A classmate's key," and enter both. Classroom keys are around 21 bits, so a laptop factors n almost instantly, rebuilds the private key, and reads the PIN. That's the moment to ask why real keys are 2048 bits.

Mallory variation. Seat a third student, using the "I'm Mallory" role, between the pair so every number passes through her. She keeps Bob's n and reads Alice her own n instead. Alice locks the PIN for Mallory, who reads it and re-locks it with Bob's real key. Bob decrypts the right PIN and nobody notices. Connect it to certificates: they exist to prove whose public key you're holding.

Factoring race

RSA's public key includes n = p × q. If Eve can split n back into p and q, she can rebuild the private key. Your device will try the simplest way: dividing n by every odd number until one fits.

What real attackers do, and the quantum question

Trial division is the slowest possible method. The best classical algorithm, the general number field sieve, is enormously faster, and in 2020 researchers used it to factor the 829-bit challenge number RSA-250 with roughly 2,700 CPU core-years of computing. That's why 2048-bit RSA is rated at about 112 bits of security, the last row in the table, rather than 1,024. It remains far out of reach.

A large quantum computer running Shor's algorithm would factor n efficiently. None exists yet, but because recorded traffic could be decrypted later, NIST has standardized post-quantum replacements (ML-KEM for key establishment, ML-DSA for signatures) and published a draft plan to phase out RSA over the next decade.

Which key?

The question certification exams ask most. Encrypting uses the receiver's public key. Signing uses the sender's private key. Try each scenario.

The RSA cheat sheet

To keep it secretEncrypt with the receiver's public key. They decrypt with their private key.
To prove who sent itSign with the sender's private key. Anyone verifies with the sender's public key.
  • RSA only locks a couple of hundred bytes. Real messages use hybrid encryption: RSA locks an AES key.
  • Use OAEP padding for encryption and PSS for signatures. Textbook RSA without padding leaks patterns.
  • Security rests on how hard it is to factor n. Use at least 2048-bit keys; a large quantum computer would break RSA.
  • Public keys need proof of ownership (certificates), or Mallory can swap in her own.

Where RSA shows up today

  • HTTPS certificatesMost websites still prove their identity with an RSA signature in their certificate chain. In TLS 1.3 the keys themselves come from an ephemeral Diffie-Hellman exchange; RSA's job is the signature.
  • SSH keysssh-keygen -t rsa -b 4096 is still common, though Ed25519 keys are now the usual default.
  • Code and document signingSoftware updates, drivers, and signed PDFs use signatures so you can tell the file wasn't altered.
  • Encrypted email and filesPGP and S/MIME use the hybrid pattern from tab 5: RSA locks a one-time key that encrypts the message.
Inspect a real RSA key in your browser

Visit any HTTPS site and click the icon at the left of the address bar, then open the connection or certificate details. Look for "Subject Public Key Info." If it says RSA, you'll see a 2048 or 4096-bit modulus (that's n) and an exponent of 65537 (that's e). Some sites show an elliptic-curve key (ECDSA) instead, which does the same signing job with a much smaller key.
